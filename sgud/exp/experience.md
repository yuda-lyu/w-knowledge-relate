## 審計之心得（套件設計與審計中累積）

1. **回退不是撤銷，且各套件皆然**：關聯之刪除／還原不對稱、以新進之閘重收舊邊而改值或遺失；值回退無條件覆寫套用後之改動。處置：回退＝撤銷該次處置之效果（只還原該次改過之單位；現值已非該次結果者報衝突、`acceptCurrent` 明示才取代）；撤銷（`undoDeleteNote`）與重新收件（`restoreNote`）分立為兩種契約。對標：補償交易、`git revert`／If-Match、Kubernetes Server-Side Apply 之欄位擁有權。
2. **待判之生命週期與檢核紀錄要單一規則**：存量重排使用者負責之邊、失敗路徑覆寫負責者、判定成立不結案使用者待判。處置：中止不計、失敗計；未判不記已審；未能判定不得算合格；使用者之裁示不被推翻（素材雜湊變了才重提）；tries＝登錄後失敗次數。
3. **記憶體中之工作不持久即丟**：RS4 暫緩提案只在記憶體、刪除／還原之半狀態無偵測。處置：先記後寫；半狀態每輪偵測並發必看字樣；JSON 帳逐帳驗結構、JSONL 讀寫只一份。
4. **檢核版本未涵蓋判定所讀之素材**：RS4／RS6 之雜湊只含兩端之版本時刻，判定所讀之內容改了不重核——核對雜湊納入材料（`createCheckHasher`）。
5. **三份判定小組執行器三語意**：以摘要套件 `runPanelPage` 之 opt-in 擴充收斂為一份；第三席中止後其後之頁需第三席者不判（刻意之差，測試改期望）。
6. **層序要守門才不會回頭**：`relateStage` 一檔七職、stages↔ops 雙向——拆分後由 `unit-relate-package` 守層序。
7. **差分夾具是每步之安全網**：重構前後以夾具逐案比對新舊輸出（組裝、詞彙、提示詞 golden、評分規劃之鍵），0 差才過。
8. **免費席重跑題組是換席之前提**：RS5 票驗證改了即重跑題組（每案兩回）；無逐案兩回全過者即不換席，目錄已漂之 id 另通報。
9. **本套件之守門會擋新寫之註解與字串**（下游工作之名、裸寫之 `'RS5'` 字面，見 `unit-relate-package` ④、`unit-relate-holds` ④）——一律中立措辭。
10. **套件改結構後，以檔案位置定根之測試先紅**（2026-11-02）：原始碼移入 `src/` 後，原以「本檔位置上一層」掃描原始碼之結構測試（`unit-relate-{domain,holds,entry,registry,standards,bench,audit}`、`unit-vocab`、`unit-relate-log-contract`、`unit-relate-stockfix`、`unit-relate-assembly`）撲空或掃進 `tmp/`、`dist/`、`docs/`；改法為掃描／讀檔根改 `<根>/src`，且 `unit-relate-package` 之全套件掃描排除產物夾 `tmp`、`dist`、`docs`（GEN-09）。
11. **編譯 exit 0 不等於可載入**：`opencc-js/dict/*` 列 external 則 `require(dist)` 即拋 `split` 非函數；`external` 以 import 字串逐字比對（`'fs'` 不涵蓋 `'node:fs'`），故 `src/` 與自有套件之 node 內建模組須同一無前綴寫法；改 `toolg/gDistRollup.mjs` 清單後必以 `require` 載入 dist 並比對匯出鍵（`unit-relate-package` 不編譯，由人於發布前核）。
12. **JSDoc `@example` 須實跑**：補範例時每則皆寫暫存腳本實際執行、`// =>` 取真實輸出；範例內需檔案者於範例內建臨時資料夾並刪除，AI 一律以固定回覆之替身；補完以「去掉全部 `/** */` 後與補前快照逐字比對」證明程式碼未動。
13. **用法字串直接執行才印**：`node src/bench/cli.mjs --help` 與失敗訊息只在直接執行時產生，import 式測試看不到；改路徑後須另起行程直接執行驗（`unit-relate-bench`〈印出之命令列用法〉案）。

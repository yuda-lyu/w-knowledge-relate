# 處理要點 — 檢定標準之運維（w-knowledge-relate）

> 路徑基準:原始碼在 `src/`,本檔所列檔案路徑除已標 `src/`、`test/`、`toolg/` 者外皆相對 `src/`.
> 本檔為本套件提供之維運能力(符合度掃描、存量處置、AI 標準之開啟、待判)與其判準;寫入型操作(存量處置與回退等)之取鎖、備份、同意由使用端負責.變更與驗收之共通要點見 `process_common.md`;現況以本套件 `sgud/state/state.md` 與 README 為準.

## 檢定標準之運維(規則帳本 STD-*)

- **符合度**:管線每輪結束可自動掃一次確定性標準(`relate.standards.scanEachRun: true`;預設 false——掃描逐邊讀兩端筆記,大庫耗時,由使用端依庫規模開啟):於管線之後、執行摘要之前掃,RS1／RS2／RS3／RS8 逐件判定(與新進之納入閘同一判定 `checkEdge`;不呼叫 AI),AI 標準(RS4／RS5／RS6)列檢核紀錄與待判;計數(抓取套件之 `standardsCountsOf`)入 `run.json` 之 `standards`;本輪已逾時間預算者略過,失敗只留 WARN.外部巡檢依 `run.json` 判讀:違反數 > 0 必看;「違反數較前次掃描增加」時,新進之納入閘應已擋——若非標準升版(`RELATE_STANDARDS` 各列之 `v`,程式判定者取自 `EDGE_STANDARDS`)所致,查寫入入口:寫邊入口須列於各標準之 `enforcedAt` 或 `RELATE_UNGATED_WRITE_ENTRIES`(撤銷、機械改寫),不在者即缺陷(`unit-relate-registry` 釘住表之內容與每個執行處之檔與函數存在;新增寫邊入口須同步補表).盤點:`git grep -nE "persistEdge\(|writeEdge\(" -- src`(寫邊入口之候選,逐一對照上述表)、`git grep -nE "relations\.del\(" -- src`(刪邊只經 `stores/edgeRetire.mjs` 之 `retireEdge`).明細(唯讀):`auditRelateStandards({ stores, domain, locale? }, { only, material, materialOf, onNote, maxIds })`——回傳逐標準之總量、合格／不合格／未能判定／不適用／已豁免與完整 id(`violations`、`undetermineds`、`waiveds`;`maxIds` 限每態列出之 id 數;`only` 限標準 id),RS1／RS2／RS8 另有資訊項(`info`／`infos`:沿革條目之違反、理由之句界截短;不算邊本身之違反),AI 標準(`ai`)列已檢、四態、版本過時與待判之未結／已豁免(來源集合未給者為 `null`,不報為零);RS8 之材料(兩端筆記之內容章＋原文標題)讀不到者記未能判定(`material: false` 則理由含數字者一律未能判定並註明);對外形狀 `relateScanOf(rep)`.未能判定不得算合格;已豁免是裁示,不是合格.
- **存量處置(寫入型;使用端須確保管線不在跑〔取執行鎖或停排程〕、先一致備份 db／knowledge／state、正式庫須使用者同意——本套件不取鎖、不備份、不呼叫 AI)**:①預演 `planEdgeStockFix(deps, { stds, ids, limit })`(不寫;回傳 `items`、`unfixable`〔RS3 確定性修正做不到者〕、`resolvable`〔本套件所登錄之使用者待判而邊之現值已合格者〕、`counts`)→ 呈報件數與修不了者 ②同意後 `applyEdgeStockFix(deps, plan, { at, ledgerFile, onEdgeFixed })`(RS3 逐條以現值重算再寫——理由與沿革之理由轉正體,id、型別、`updatedAt` 不動;RS2／RS8 須重寫理由,登錄待判交兩席改寫:非衝突型交既有邊覆核、衝突型交衝突核對;RS3 修不了者以現值重判分流〔`stale`／交兩席改寫／只剩沿革者登錄使用者待判 `edge:<邊 id>:RS3`〕;`resolvable` 者結案;處置帳預設 `<state>/stock-fix.jsonl`,逐筆記帳,可由 `readEdgeStockLedger` 讀回;單件失敗隔離入 `errors`)③隨即重掃(`auditRelateStandards`)＋連鎖斷言 `verifyEdgeStockChain(deps, rows)`(邊仍在、`updatedAt` 未被改、理由已合正體、RS4／RS6 檢核紀錄之雜湊已隨修正換值;覆核列與待判列之登錄存在、結案列已結案;呼叫端自有之連鎖——如讀關聯之下游之邊庫快照——經 `onEdgeFixed` 處置、由呼叫端驗)④**回退判準**(判準由使用端組裝;本套件提供預演、套用、連鎖斷言、回退四件):連鎖斷言有問題(`problems` 非空)、套用失敗(`errors` 非空)、或重掃之不合格多於應剩之件數(全量:修不了者之件數;限量〔`limit`〕:套用前之不合格數減已套用之件數——限量時先以同一口徑掃一次;RS2／RS8 交兩席改寫者除外,其違反待兩席改寫後才消失)→ 回退:`readEdgeStockLedger(file, { since })` 取帳列,呼叫端依帳之全域逆序逐列交 `rollbackEdgeStockFix(deps, rows, { onEdgeRolledBack, acceptCurrent })`(他模組之列略過)——**回退＝撤銷該次處置之效果**:只動該次所改之單位(理由、被修之沿革理由),其後被改動之單位或邊已不在者報 `conflicts`(不覆寫、不復活;`acceptCurrent` 記取代列),覆核與待判只動同一登錄(使用者其後之豁免不被改寫);回退後以 `readEdgeStockLedger` 不再列已回退者 ⑤套用與回退回傳受影響之兩端(`affected`),由呼叫端 `projectAffected` 投影 ⑥確認後恢復管線.預演純讀(規則帳本 STD-26),已不再違反之待判結案與回退見 STD-29,回退契約見 STD-25.
- **AI 標準之開啟(皆須使用者同意)**:①該標準之題組以**正式席位**逐案兩回全過:`node src/bench/cli.mjs --role <conflict-check｜edge-review｜reeval> --models <正式席位之條目 id,…> --runs 2 --out <專案外目錄> [--env <金鑰檔>]`(內建通用題組;用自己的題組 `--cases <題組.json>`,配 `--vocab <詞彙.json> [--vocab-pick]`;每案各回之類別皆等於應然才算通過,不以比率放行;標準與角色對應:RS4＝`conflict-check`、RS5＝`reeval`、RS6＝`edge-review`,納入閘＝`relate`;詳 README §14).提示詞或題組一改,`planRelateBench(角色).promptFp` 即變(與 `模型評比.csv` 之「提示詞指紋」欄對照,做法見 `process_common.md` 流程 5),須以正式席位重跑該角色 ②席位核對:判定小組之首兩席須不同家,且第一席須異於提案席(`relate.ai`／`relate.reverse.ai` 之實際成交者)——否則兩票恆為同一供應者,判定永遠不成立(重評與既有邊覆核之升級提案以 first＋second 投票,衝突核對之新衝突以提案席＋first 投票).以 `relatePanelsOf(resolveRelateSettings(cfg))` 看各組之成員、必填與投票組合(`ballots`);總組裝之啟動期同家警告(`info().startupWarnings`,每輪開頭以「啟動期檢核：」記入日誌)與必填席檢核(`relateFeatureProblems`:已開啟之功能缺判定小組必填席或 domain 成員即建構期拋錯——衝突核對須 first〔既有邊另需 second,未設時既有邊不核〕、既有邊覆核須 first＋second)同讀這一份 ③改設定開關與配額:`relate.standards.conflictCheck { enabled, perRun }`、`relate.standards.edgeReview { enabled, perRun, deadline }`、判定小組席位 `relate.standards.ai.{first,second,third}`.既有邊覆核(RS6)開啟時可設 `relate.standards.edgeReview.deadline`(ISO 日期,`''` 不設;隨關聯段報告帶出 `rs6Deadline`,供外部巡檢依近輪消化速度判「趕不上／已逾期仍有未核」).重評(RS5)之套用閘門 `relate.reeval.apply` 之開啟程序見關聯處理要點.
- **AI 標準之容量**(開啟前依「容量 ≥ 進料」定配額與席位;以使用端自己的庫量,每庫不同):呼叫數為下限＝兩席各 1 次／頁(`pageSize`,預設 10),另加第三席(兩席不一致時)、修訂與修訂後重判.量法:RS6 存量＝`reviewQueueOf`(`quota` 0)回傳之 `total − done`(每輪入報告 `rs6Total`／`rs6Done`)、RS4 存量＝衝突邊中無有效 RS4 檢核紀錄者(`stockProgressOf` 之 `total − done`;`rs4Total`／`rs4Done`),皆 ÷ `pageSize` × 2 為存量一次全量之呼叫數下限;進料＝邊之 `createdAt` 近 7 日逐日計數(兩端內容變更者另計).RS6 一開即須至少消化進料才不積壓;存量以每日餘量消化,`relate.standards.edgeReview.deadline` 依此推算.
- **待判**:待判登錄(鍵 `<物件>:<id>:<標準>`,邊為 `edge:<邊 id>:<標準>`;集合 `holds`)之列表、逾期、要求重試、豁免——`listHolds(holds, filter)`、`overdueHolds`、`requestRetry(holds, id, { at })`、`waiveHold(holds, id, { by, ruling, at })`——屬抓取套件(待判登錄為各工作同一機制),本套件不轉出;本套件之待判字樣(原因與下一步)一律指本套件之 API 與選項(`RELATE_HOLD_NEXT`),期限一律 `relateHoldDeadlineOf`.各待判之「下一步」即可完成之處置(還原類寫明 `restoreEdge`〔`apply`、`reason`〕等);使用者豁免是對該邊該標準之裁示,掃描記為已豁免、存量處置不重開(`stockWaiverKeyOf`).
